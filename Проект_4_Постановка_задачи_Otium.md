> Проект по системному анализу: от интервью с заказчиком до диаграммы последовательности, тестирования REST API и постановки задачи на разработку.

**Коммуникация:** Telegram — чат группы; Яндекс Телемост — созвоны

## О проекте

Заказчик Otium заметил, что пользователям сложно выбрать, что посмотреть: приходится сравнивать по десять фильмов, смотреть трейлеры, а часть пользователей просто уходит с платформы, не досмотрев до выбора.

**Решение:** добавить рейтинг кинокритиков рядом со зрительским и разрешить сортировку списка по любому из двух рейтингов.

На интервью выяснилось, что рейтинг критиков есть не у всех фильмов и сериалов — например, у детского контента. Ставить таким позициям ноль было неудобно: при сортировке по возрастанию они попадали бы в начало списка. Договорились, что фильмы и сериалы без рейтинга всегда остаются в конце списка, независимо от направления сортировки.

## Что сделано

### 🔍 Извлечение требований

В исходном запросе заказчик просил добавить рейтинг критиков. Сортировку и фильтрацию по этому рейтингу обсудили отдельно во время интервью.

### 🔀 Диаграмма последовательности

Построил диаграмму последовательности для новой функции, как запрос на сортировку проходит от пользователя через веб-сервер к сервисам «Фильмы» и «Сериалы» и обратно.

### 🧪 Тестирование существующего API

Мы проверили существующее REST API в Swagger: Web Server API, Films Server API и Series Server API. Сверили доступные поля и параметры с требованиями новой функции.

### 🛠️ Постановка задачи разработчику

По результатам тестирования я описал изменения для всех трёх API:

| API | Изменение |
|---|---|
| Films Server, Series Server | Добавить необязательное поле `criticsRating`: рейтинг есть не у всех фильмов и сериалов |
| Web Server | Принимать query-параметр `sortBy`, который выбирает зрительский рейтинг или рейтинг критиков |
| Web Server | Принимать query-параметр `direction` со значением сортировки по возрастанию или убыванию |
| Web Server | Возвращать `criticsRating` и в списке, и в детальной карточке |

Оформили всё это тикетами на разработку для каждого из трёх API.
