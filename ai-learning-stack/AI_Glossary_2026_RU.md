**Версия:** 2026.10.04.3

## A

**Протокол «агент — агент» (A2A, Agent-to-Agent Protocol)**  
Правила и спецификации, по которым независимые интеллектуальные агенты находят друг друга (discovery), делегируют задачи (delegation) и взаимодействуют между собой. Не путать с MCP (который связывает агент ↔ инструменты/данные). Протокол A2A регулирует связь агент ↔ агент.

**Фонд агентного ИИ (AAIF, Agentic AI Foundation)**  
Вендор-нейтральный целевой фонд (directed fund) под эгидой Linux Foundation, управляющий развитием открытых стандартов для агентов (MCP, A2A, AGENTS.md, goose и др.), чтобы ими не владел один поставщик моделей.

**Протокол коммуникации агентов (ACP, Agent Communication Protocol)**  
Ранний стандарт однорангового обмена сообщениями (peer-messaging); его идеи и наработки были объединены с протоколом A2A. В настоящее время самостоятельной актуальной спецификацией не является.

**Актуатор (Actuator / инструмент изменения состояния)**  
Инструмент или действие, которое **меняет** внешнее состояние систем: запись в базу данных, отправка сообщения или письма, проведение платежа, создание тикета, изменение конфигурации. Из-за высокого риска почти всегда требует подтверждения человеком (Human-in-the-Loop, HITL).

**Адаптивное мышление / адаптивный вывод (Adaptive Thinking / Adaptive Inference)**  
Подход, при котором модель тратит больше внутренних скрытых шагов рассуждения на сложные аналитические задачи и меньше — на тривиальные. Напрямую связано с тарифицируемыми токенами рассуждения (billed thinking tokens / test-time compute).

**Файл инструкций для агентов в проекте (AGENTS.md)**  
Короткий файл руководства по репозиторию (project-guidance) для кодирующих агентов (вклад AAIF). По смыслу аналогичен компактному индексу базы знаний (thin Knowledge Base index).

**Среда выполнения агента / хост (Agent host / runtime)**  
Программное окружение вокруг модели: обеспечивает вызов инструментов, диалог с человеком (HITL), сбор логов, контроль бюджетов и работу MCP-клиента. Не путать с самой языковой моделью (LLM).

**Траектория агента (Agent trajectory)**  
Полный сквозной путь решения задачи: цепочка макросостояний (macro-states), промежуточных шагов, вызовов инструментов и пауз в ожидании человека. Используется для оценки качества (eval) и разбора сбоев.

**Агентный режим / агентность (Agentic)**  
Режим работы, при котором система не просто генерирует текст, а **самостоятельно планирует шаги, вызывает внешние инструменты, сохраняет контекст в памяти и производит действия в реальном мире**. OWASP публикует два раздельных списка: LLM Top 10 (модель как компонент) и Agentic Top 10 (система как действующий субъект/актор).

**Список разрешённого (Allowlist / белый список)**  
Явный закрытый перечень разрешённых сущностей (инструментов, действий, состояний). Всё, что не вошло в список, считается строго запрещённым.

**Протоколы сети агентов (ANP, Agent Network Protocol и аналоги)**  
Экспериментальные протоколы децентрализованной идентификации и организации сетей агентов. Имеют ограниченное применение в реальном продакшене.

**Антипаттерн (Anti-pattern / нежелательный шаблон)**  
Привычное инженерное решение, которое кажется удобным на этапе демо, но системно разрушает надёжность, безопасность или экономику (cost) в промышленной эксплуатации.

**Приложения MCP (Apps / MCP Apps extension)**  
Официальное расширение стандарта MCP для интерактивного интерфейса (UI), когда инструменту требуется отобразить человеку веб-форму или элементы управления, а не только текст.

**Идентификаторы рисков агентных систем (ASI01–ASI10, Agentic Security Identifiers)**  
Номера угроз в рейтинге OWASP Top 10 for Agentic Applications (риски уровня системы как активного субъекта). Включают такие векторы, как перехват целей (ASI01), отравление памяти (ASI06), каскадные сбои (ASI08) и эксплуатация доверия (ASI09). Не путать со списком уязвимостей моделей LLM01–LLM10.

**Журнал аудита (Audit trail)**  
Неизменяемый журнал (append-only): кто, какой инструмент вызвал, с какими аргументами (с маскированием секретов), каков результат, задержка и от чьего имени (principal). Необходим для расследования инцидентов и комплаенса.

## B

**Базовый уровень (Baseline)**  
Минимально достаточная архитектурная основа «по умолчанию». Например, гибридный поиск (hybrid retrieval) является базовым стандартом, а графовый поиск подключается только при реальной необходимости.

**Алгоритм BM25 (BM25 lexical ranking)**  
Классический алгоритм текстового ранжирования по ключевым словам. В гибридном поиске сочетается со смысловым векторным поиском (vector search).

**Изначально цифровой PDF (Born-digital PDF)**  
Документ PDF, сгенерированный из текстового редактора или верстки, а не полученный путём сканирования бумажного листа. Извлекается проще и чище, чем скан.

**Ограниченный по ущербу (Bounded)**  
Принцип проектирования, при котором последствия сбоя локализованы. Ограниченное исключение (bounded exception) не может перерасти в каскадное разрушение всей системы.

**Бюджет ресурсов (Budget: steps / tokens / time / spend)**  
Жёсткий лимит на одну задачу: потолок по шагам, токенам, времени выполнения (wall-clock time) и затратам. При исчерпании система останавливается и формирует отчёт для человека.

## C

**Канонические паттерны составных систем (Canonical patterns of Compound AI Systems)**  
7 отраслевых уровней архитектуры: 1) Одиночный вызов расширенной модели; 2) Цепочка промптов; 3) Маршрутизатор; 4) Параллельное ветвление; 5) Конвейер с барьерами; 6) Оценщик-оптимизатор; 7) Автономные циклы/супервизоры.

**Маршрутизация по способностям (Capability-based routing)**  
Выбор класса (tier) модели на основе требуемого для шага умения (сложная логика, написание кода, длинный контекст, экономичность), а не по маркетинговому бренду.

**Журнал изменений (Changelog)**  
Краткая история версий файла, предотвращающая расхождение (drift) между Ядром, Стандартами и Индексом.

**Фрагмент / нарезка документа (Chunk / chunking)**  
Текстовый фрагмент, помещаемый в поисковый индекс. Предпочтительна разбивка по смысловой структуре (semantic chunking), а не слепая нарезка на равные части (fixed-size).

**Непрерывная интеграция (CI, Continuous Integration)**  
Автоматизированный запуск тестов при каждом изменении, включая прогон эталонного набора (golden-set regression) для проверки поиска и логики агента.

**Авторазмыкатель цепи (Circuit breaker)**  
Механизм принудительной остановки бесконечного цикла или лавины повторных запросов (retry storm) с передачей задачи человеку (эскалация).

**Холодный старт (Cold start)**  
Дополнительная задержка (latency) при первом запросе после простоя. В составных конвейерах (compound pipelines) задержки холодного старта **умножаются вдоль цепочки вызовов**.

**Сжатие контекста с сохранением сути (Compaction)**  
Интеллектуальное сжатие истории диалога или траектории с **сохранением ключевой цели и ограничений задачи** (anchored summarization), превосходящее простое усечение (truncation).

**Составная ИИ-система (Compound / Compound AI System)**  
Система, построенная не на одной универсальной модели, а на композиции ролей (см. Канонические паттерны): маршрутизаторы, специализированные модели, модули поиска, контрольные шлюзы и внешние инструменты.

**Вычислительный инструмент (Compute tool class)**  
Инструмент, производящий расчёты, выполняющий код или отрисовку в песочнице (sandbox) без прямого изменения данных в бизнес-системах. Средний уровень риска.

**Статусы достоверности знаний (CONFIRMED / UNKNOWN / DEPRECATED)**  
Метки достоверности фактов и поисковых фрагментов: ПОДТВЕРЖДЕНО, НЕИЗВЕСТНО, УСТАРЕЛО. Защищают агента от использования черновиков как неоспоримых правил.

**Слой жёстких запретов (Constraints)**  
Единственное место в архитектуре, где сосредоточены безусловные запреты уровня «НИКОГДА НЕ» (NEVER / MUST NOT). Не смешиваются с операционными политиками (Policies).

**Окно контекста (Context window)**  
Объём информации (токены), который модель может обработать за один вызов: системные правила, история, схемы инструментов и текущий вопрос. Конечный ресурс.

**Продолжение пакетной выдачи (Continue / multi-batch deliverable)**  
Операция продолжения генерации прерванного пакета документов знаний со следующей части без повторного согласования всего манифеста (если архитектура и параметры не менялись).

**Системное ядро (Core / System Core)**  
Статическая «конституция» агента: роль, конечный автомат состояний (state machine), защитные ограничители (guardrails), участие человека (HITL), приоритет источников и формат вывода. Не является хранилищем секретов.

**Цена ошибки (Cost of error)**  
Уровень ущерба от неверного ответа или ошибочного действия. Чем выше цена ошибки, тем мощнее выбирается модель, тем глубже самопроверка (Self-Check) и строже контроль человека.

**Стоимость успешной задачи по правилам (Cost per completed compliant task)**  
Ключевая экономическая единица (unit economics): реальная стоимость одной **успешно и корректно решённой** бизнес-задачи, а не просто абстрактная цена за миллион сожжённых токенов.

**Модель точной пересортировки (Cross-encoder / re-ranking model)**  
Нейросеть для повторного ранжирования, оценивающая пару (вопрос, фрагмент) глубже и точнее векторного сходства. Затратна по ресурсам, поэтому применяется только к короткому списку кандидатов.

**Перекрёстные ссылки (Cross-references)**  
Указатели на другие файлы базы знаний по их именам без дублирования фундаментальных правил, описанных в единственном месте (sole-location rules).

## D–G

**Доверие данным (Data Trust)**  
Принцип архитектуры: любой внешний контент (веб, ответы инструментов MCP, фрагменты RAG, файлы пользователей) признаётся **данными**, а не руководящими инструкциями. Он не имеет права переписывать Системное ядро, политики безопасности или зафиксированные параметры проекта.

**Итоговый результат этапа (Deliverable)**  
Формальный артефакт стадии проектирования (пользовательские истории, схема процесса, манифест инструментов, паспорт системы), обычно оформляемый в едином изолированном блоке кода (isolated code block) для удобного копирования.

**Политика устаревания функций (Deprecation policy)**  
Правило стандарта MCP: устаревшая функция остаётся в спецификации не менее 12 месяцев с обязательной инструкцией по переходу (migration note).

**Конвейер проектирования (Design pipeline)**  
Режим работы, при котором Системное ядро выступает ведущим методологом и ведёт проектировщика через анализ требований к созданию архитектуры и пакета инструкций для *будущего* агента.

**Архитектурные результаты (Design/architecture deliverables)**  
Спецификации архитектуры и паспорта систем. Как правило, составляются на английском языке (English) для международной совместимости (interoperability), тогда как диалог ведётся на рабочем языке проекта.

**Прямой доступ к правилам (Direct Access)**  
Чтение конкретного файла Навыка (Skill) или Стандарта (Standard) по точному имени, в отличие от семантического поиска похожих фрагментов в Справочниках.

**Дрейф системы (Drift)**  
Скрытая постепенная деградация: расхождение версий файлов, падение точности поиска, увеличение числа шагов агента. Сигнал к доработке архитектуры контура.

**Двойное подтверждение (Dual gate)**  
Обязательный барьер до начала архитектурного этапа: (1) явное подтверждение блока параметров проекта; (2) утверждение аналитических артефактов.

**Векторное представление (Embedding)**  
Преобразование текста/изображений в числовые векторы для поиска по смыслу. Версия модели векторизации должна быть жестко зафиксирована (version-pinned).

**Состояние эскалации (ESCALATE macro-state)**  
Макросостояние конечного автомата: при исчерпании лимита шагов, тупике или высоком риске агент передаёт управление человеку.

**Оценка качества по эталону (Eval / evaluation)**  
Регулярное измерение метрик системы на фиксированном эталонном наборе (golden set). Неотъемлемая часть архитектуры конвейера, а не разовая задача перед запуском.

**Чрезмерная автономия (Excessive Agency, уязвимость LLM03)**  
Ключевой риск по OWASP: выполнение агентом необратимых действий без согласования.

**Фактическая достоверность / верность контексту (Faithfulness)**  
Метрика генерации: каждое утверждение в ответе строго подтверждается найденным контекстом, исключая галлюцинации.

**Примеры в промпте (Few-shot prompting)**  
Включение нескольких образцов «входные данные → ожидаемый ответ» в текст системного промпта.

**Флагманский класс моделей (Frontier tier)**  
Наиболее способные закрытые модели для самых сложных задач с высокой ценой ошибки.

**Метаданные в начале файла (Frontmatter)**  
Структурированный блок (обычно в формате YAML) в начале файла: имя, версия, триггеры, инструменты и состояния.

**Шлюз инструментов (Gateway / MCP gateway)**  
Промежуточный защитный прокси перед серверами инструментов: проверка JSON-схем, инъекция идентичности, маскирование секретов и сбор телеметрии.

**Эталонный набор тестов (Golden set / gold set)**  
Фиксированный набор пар «запрос → нужные фрагменты / верный ответ / ожидаемая траектория».

**Фреймворк goose**  
Локальный (local-first) open-source ИИ-фреймворк от компании Block. Один из трех первоначальных проектов-основателей Agentic AI Foundation (наряду с MCP и AGENTS.md).

**Графовый поиск (GraphRAG)**  
Метод RAG, усиленный графом сущностей и связей для логических цепочек (multi-hop).

**Защитные ограничители (Guardrails)**  
Входные и выходные фильтры, белые списки, программные шлюзы (HITL). Дополняют текст промпта на уровне кода.

## H–J

**Программная обвязка агента (Harness / agent harness)**  
Инфраструктурный слой вокруг модели: управление контекстом, подгрузка схем инструментов по запросу, сжатие истории (compaction), изолированная песочница, бюджеты.

**Человек в контуре (HITL, Human-in-the-Loop)**  
Принцип управления рисками: агент подготавливает операцию, а человек (или другая система) её утверждает.

**Роли протокола MCP (Host / Client / Server)**  
- **Хост (Host)** — вызывающее приложение;  
- **Клиент (Client)** — коннектор внутри хоста;  
- **Сервер (Server)** — внешний сервис, предоставляющий ресурсы, инструменты или шаблоны промптов.

**Гибридный поиск (Hybrid RAG / Hybrid Search)**  
Совместный поиск документов по смыслу (vector search) и по точным совпадениям слов (lexical search, например BM25). Производственный стандарт по умолчанию.

**Идемпотентность / ключ идемпотентности (Idempotent / idempotency key)**  
Свойство операции: повторный вызов с тем же ключом не приводит к повторному изменению состояния.

**Реестр базы знаний (Index / KB Index)**  
Компактный файл-оглавление (≤ 100–150 строк), содержащий перечень файлов, их версии, категории. Служит для прогрессивного раскрытия контекста.

**Загрузка данных в поиск (Ingestion)**  
Конвейер: очистка текста → нарезка (chunking) → разметка → векторизация → индексация.

**Спецификация JSON Schema 2020-12**  
Обязательный стандарт описания схем инструментов в актуальном протоколе MCP, сменивший слабо-типизированные старые стандарты для устранения галлюцинаций параметров.

## L–N

**Ограничение автономии (Least Agency)**  
Сдвиг парадигмы от простого «наименьших привилегий» к строгому управлению агентами как нечеловеческими идентичностями (NHI) с ограниченным жизненным циклом и динамическим отзывом прав доступа.

**Принцип наименьших привилегий (Least privilege)**  
Выдача каждому инструменту строго необходимого минимума прав.

**Большая языковая модель (LLM, Large Language Model)**  
В архитектуре 2026 года является лишь **одним из компонентов** составной системы (вероятностным движком).

**Топ-10 рисков языковых моделей (LLM01–LLM10, OWASP GenAI LLM Top 10)**  
Перечень уязвимостей моделей, используемых как пассивные компоненты. Не путать с Agentic Top 10.

**Синхронное версионирование (Lockstep versioning)**  
Правило обновления версий: Системное ядро, управляющий им Стандарт и Индекс повышают версию строго в одном проходе.

**Макросостояние (Macro-state)**  
Крупная ключевая фаза жизненного цикла агента. В диалоге обычно фиксируется якорем `[CURRENT_STATE: … | STEP n/L]`.

**Протокол контекста модели (MCP, Model Context Protocol)**  
Открытый стандарт подключения языковых моделей к внешним данным и инструментам под эгидой AAIF. Ревизия 2026-07-28 работает без сохранения состояния (stateless-first).

**Слой памяти (Memory Layer)**  
Подсистема хранения информации о текущей сессии или долгосрочном контексте конкретного пользователя. Не путать с корпоративной базой знаний (RAG).

**Средний класс моделей (Mid-tier model / Strong balance)**  
Оптимальный класс моделей по соотношению цены и качества.

**Многораундовые запросы (MRTR, Multi Round-Trip Requests)**  
Паттерн MCP: при нехватке параметров сервер возвращает статус «требуется ввод» с непрозрачным токеном, а клиент досылает данные без удержания соединения.

**Многошаговый логический переход (Multi-hop reasoning)**  
Ответ требует цепочки выводов (A связано с B, B с C). Показание к применению GraphRAG.

**Нечеловеческие идентичности (NHI, Non-Human Identities)**  
Класс управления доступом: агенты в корпоративной сети управляются как NHI, с выдачей временных сертификатов и полным аудитом действий.

**Руководство АНБ/МО США (NSA/DoD Zero Trust guidance)**  
Директивы от 2 июня 2026 года, определяющие стандарты изоляции серверов MCP в DMZ и обязательного mTLS-шифрования.

## O–S

**Наблюдаемость (Observability / LLMOps)**  
Инфраструктурный комплекс сбора логов, трассировок (Trace Context) и метрик.

**Протоколы авторизации и входа (OIDC / OAuth 2.0)**  
Промышленные стандарты, применяемые для корпоративного SSO и безопасного делегирования прав инструментам (через шлюзы).

**Модели с открытыми весами (Open-weight models)**  
Модели для локального или серверного развёртывания (self-hosting: vLLM, TensorRT-LLM).

**Действие строго по согласию (Opt-in)**  
Выполнение операции (выход в интернет) только после явного подтверждения оператором.

**Перцентили задержки (p50 / p95 latency)**  
Метрики скорости. Измеряются **сквозным образом для всей задачи**, а не по отдельному вызову модели.

**Параллельное ветвление (Parallel fan-out)**  
Один из канонических паттернов: задача разбивается на независимые ветви, результаты объединяются.

**Фиксация версий (Pin / version-pinning)**  
Жёсткое закрепление конкретных версий MCP-серверов во избежание изменения поведения сторонними обновлениями (риск LLM04).

**Операционные политики (Policies)**  
Слой обязательных практических правил («Всегда делать X»). Отделяется от слоя абсолютных запретов (Constraints).

**Прогрессивное раскрытие контекста (Progressive Disclosure)**  
В контекст загружается только компактный Индекс; полные тексты Навыков и Стандартов подгружаются строго по необходимости.

**Генерация с дополненной выборкой (RAG, Retrieval-Augmented Generation)**  
Конвейер: загрузка → нарезка → векторизация → поиск (гибридный) → пересортировка → дополнение контекста → генерация.

**Справочники базы знаний (Reference / Data Dictionary)**  
Файлы нормативных фактов, словарей, структур данных. Не содержат алгоритмов (Навыков) и политик (Стандартов).

**Маршрутизатор моделей (Router / model routing)**  
Программный узел, направляющий шаг задачи на подходящий класс моделей.

**Самопроверка модели (Self-Check / Reflection)**  
Внутренний шаг проверки ответа перед отправкой.

**Сенсор (Sensor / инструмент только для чтения)**  
Инструмент для чтения данных. Сам не меняет внешнее состояние.

**Метод обнаружения сервера (server/discover)**  
Обязательный метод MCP 2026-07-28: сервер обязан сообщить поддерживаемые версии и возможности.

**Навык базы знаний (Skill)**  
Процедурный документ («Как делать»): пошаговый алгоритм и формат результата.

**Целевой уровень сервиса (SLO, Service Level Objective)**  
Измеримая целевая планка качества (задержка и стоимость успешной задачи).

**Граница источника (SOURCE BOUNDARY)**  
Правило: агент формирует ответ строго на основе предоставленного проверенного контекста. Иначе — «Данные не подтверждены».

**Приоритет источников истины (Source Priority)**  
Иерархия разрешения конфликтов данных: Требования → Ядро → База знаний → Память → Внешний веб. Формулируется один раз в Ядре.

**Стандарт базы знаний (Standard)**  
Нормативный документ («С чем сверять»): эталонные политики, критерии соответствия.

**Архитектура без сохранения состояния (Stateless MCP)**  
Свойство MCP (с 2026-07-28): каждый сетевой запрос самодостаточен, постоянные сессии отсутствуют.

**Пошаговая аутентификация (Step-Up Authentication)**  
Требование повторной аутентификации (например, биометрии) для подтверждения необратимых действий агента. Защита от эксплуатации доверия.

## T–Z

**Фоновые задачи MCP (Tasks / MCP Tasks extension)**  
Расширение MCP для длительных асинхронных операций с выдачей устойчивого дескриптора.

**Масштабирование вычислений при выводе (Test-Time Compute)**  
Дополнительные вычисления (скрытые рассуждения) **в момент генерации ответа**. Тарифицируются.

**Токены рассуждения / мышления (Thinking tokens / reasoning tokens)**  
Токены, генерируемые на скрытых шагах внутреннего рассуждения перед итоговым ответом.

**Ключи контекста трассировки (Trace Context Keys)**  
Стандартизированный механизм проброса `task_id` и `session_id` в заголовках, пришедший на смену устаревшим механизмам Roots и Logging в MCP.

**Время жизни кэша (ttlMs)**  
Параметр протокола MCP, жестко регламентирующий кэширование списка инструментов на стороне клиента для экономии сетевых запросов.

**Независимый экран согласия (Universal Login for Consent)**  
Механизм подтверждения (HITL) за пределами диалогового окна чата (через независимый экран ОС или корпоративного SSO). Защищает от фишинга, отравленных промптов и эксплуатации доверия (ASI09).

**Политика работы с вебом (Web: opt-in + label + Non-Merge)**  
Формула интернет-поиска: только по согласию, с маркировкой источника, и без автоматического слияния с корпоративной базой без человека.

**Рабочий процесс (Workflow)**  
Сквозной регламентированный процесс от начального триггера до целевого результата.

**Служебные метаданные MCP (_meta field)**  
Поле протокола MCP для передачи версий, данных клиента и возможностей без замусоривания основного текста промпта.

**Архитектура нулевого доверия для MCP (Zero Trust MCP)**  
Концепция изоляции, аутентификации (mTLS) и валидации всех вызовов инструментов агента, закрепленная в стандартах АНБ/МО США.

## Длинные формулировки из документов — простой смысл

| Формулировка в документах | Практический смысл простыми словами |
|---------------------------|-------------------------------------|
| Ограничение автономии (Least Agency) как управление NHI | Агент — это не просто скрипт, а «нечеловеческий сотрудник» (NHI). Ему выдаются временные доступы, которые можно в любой момент отозвать. |
| Независимый экран согласия (Universal Login) | Подтверждать перевод денег нужно не кнопкой «Да» в чате с ботом, а в отдельном безопасном окне, чтобы хакеры не могли подделать интерфейс чата. |
| Архитектурные спецификации на английском (English for interop) | Чертежи системы и паспорт пишутся по-английски, чтобы их без искажений понимали любые платформы. Общение с пользователем — на русском. |
| Работа с вебом: только по согласию + маркировка + без автослияния (Web: opt-in + label + Non-Merge) | Выход в интернет разрешён только по запросу. Вся информация помечается как внешняя. В постоянную базу без личного одобрения человека ничего не сохраняется. |
| Запреты не равны политикам (Constraints ≠ Policies) | «Никогда нельзя» и «Всегда делай так» живут в строго разных блоках. Параметры конкретного сеанса нельзя зашивать в текст Ядра. |
| Память не равна поиску по базе знаний (Memory ≠ RAG) | «Что мы помним о пользователе» и «Поиск по регламентам компании» — две принципиально разные подсистемы. |
| Связь агента с инструментом (MCP) и агента с агентом (A2A) | Подключение калькулятора регулируется протоколом MCP, а координация работы двух независимых агентов — протоколом A2A. |
| Сквозной уровень сервиса (Pipeline-level SLO) | Оценивать нужно общее время ожидания пользователя по всему конвейеру. Быстрая модель не спасет, если вызовов слишком много. |
| Прогрессивное раскрытие информации (Progressive Disclosure) | Не нужно отправлять всю библиотеку инструкций в каждый запрос. Загружается краткое оглавление (Индекс), полные правила — по мере необходимости. |
